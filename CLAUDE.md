# EasySpeak

React Native (Expo) iOS app for speaking practice. Solo dev. Records the user
answering a prompt, transcribes it (Deepgram), and scores delivery metrics
(pace, filler words, pauses, intonation) with AI feedback.

## Build & run

- `npx expo start` — JS bundler only. Hot-reloads JS into an existing native build. Does NOT compile native code.
- `npx expo run:ios` — full native build for the **iOS Simulator** (no physical device needed).
- `npx expo run:ios --device` — full native build to a connected iPhone.
- The `modules/expo-pitch` Swift module is a custom native module. Any change to it requires a native rebuild (`run:ios`), not just `expo start`.
- If a native build fails with stale-cache / codegen errors, reset pods:
  `rm -rf ios/Pods ios/build ios/Podfile.lock && npx pod-install && npx expo run:ios --device`
  Do NOT delete `ios/build` without re-running `pod-install` in the same step — it wipes codegen headers and nothing regenerates them (caused a 233-error cascade before).
- Simulator has no real mic — fine for "does it compile/run", unreliable for real-voice metric accuracy. Verdict accuracy must be tested on a physical device.
- **Judge performance ONLY on release builds** (`npx expo run:ios --device --configuration Release`). Debug builds (`expo start` / plain `run:ios`) run JS dev mode + Reanimated dev checks unminified and are **dramatically slower on older devices (A12/iPhone XS)** — debug jank is not real jank. Develop on `expo start` (hot reload), but never diagnose a "lag" without first re-checking it in release. (A whole session was burned "fixing" a debug-only XS animation stutter that was smooth in release.)

## Architecture conventions

- Single-file state machines over multi-route navigation for self-contained flows.
- `metrics.ts` is pure (no native/fs imports) — keep it that way so it stays Node-testable.
- Recompute-on-read (planned M4): store raw inputs (words, audio, pitch frames), recompute cheap metrics on read. Do NOT re-run expensive extraction (transcription, pitch detection) on every read.
- Finalize pattern: practice screen does transcribe + extractPitchFrames + computeMetrics + AI feedback, serializes metrics, passes via nav params; results screen deserializes (does NOT recompute). Impromptu and TTO both follow this.
- **Start-flow latency (the `generating`→`speaking`→`recording` sequence).** Each start is two SERIAL OpenAI hops — prompt-gen, then `tts.speak`'s `gpt-4o-mini-tts` synthesis (no streaming; `onReady`/`setPhase('speaking')` fires only after the full MP3 is generated + loaded) — then `r.startRecording`'s native mic setup (`requestPermissions` + `setAudioMode` + `prepareToRecordAsync`/`session.setActive`) which runs AFTER playback ends, before `setPhase('recording')` (the dead air after the prompt). Optimizations applied 2026-06-26: (1) `useRecording().prewarm()` requests mic permission off the hot path — both screens call it at `handleStart` start, so the first-launch dialog lands during the loader (not after the prompt) and later sessions get a cached permission hit; (2) **TTO pre-fetches the next round's prompt** during the current round's recording (`nextPromptRef`, kicked off in the round-advance effect, awaited in `handleStart`, cleared in `handleRetry`) — kills a full LLM round-trip from rounds 2 & 3's `generating` wait (`generateTTOPrompt` never rejects, so awaiting the stored promise is safe). **Speaking→recording gap FIXED (2026-06-29, device-verified — "this is better").** The dead air was the iOS audio session being **deactivated then reactivated**, NOT `prepareToRecordAsync` being slow: the TTS player tore the session down the instant the prompt finished, so the recorder paid the ~1s audio-hardware warm-up to reactivate it (known expo-audio issue #40531; Apple's guidance is to stay in `playAndRecord` and keep the session active across a playback→record handoff). Two-part fix: (1) `useAudioPlayer(null, { keepAudioSessionActive: true })` on the TTS player (`lib/tts.ts`) so the session is NOT torn down when the prompt finishes; (2) `useRecording().prepareRecording()` — called in each screen's `tts.speak` `onReady` — front-loads the permission check + `setAudioModeAsync({ allowsRecording: true })` (the `playAndRecord` category switch) DURING playback. So at record time the session is already active AND already the right category → no deactivate/reactivate cycle; `startRecording` then only fires `prepareToRecordAsync` + `record()` (kept ADJACENT, after playback). ⚠️ **DEAD END — do NOT re-try:** moving `prepareToRecordAsync` ITSELF into the playback window records SILENCE — a recorder prepared while the TTS player still owns the session goes stale when playback ends (the duration timer ticks but zero audio is captured); it must stay adjacent to `record()`. Minor open follow-up: `keepAudioSessionActive` leaves the session active after the flow ends; if it ever feels "held" (other apps' audio ducked after a session), deactivate on flow-exit via `setIsAudioActiveAsync(false)`. Backend move (M1) would also collapse the two serial OpenAI hops.
- `serializeMetrics`/`deserializeMetrics` exist because `SessionMetrics` holds `Set`s that don't survive `JSON.stringify` through nav params.

## Navigation

Two zones, one rule: route cross-zone / cross-step moves through the verbs in
`lib/navigation.ts`, never raw `router.push/replace/back`.

- **TAB zone** — `(tabs)/` Home / Practice. Always the stack root.
- **FLOW zone** — focused tasks pushed on top of the tabs: `impromptu`,
  `explain`, `storytelling`, `debate`, `tto-explainer`, `tto-practice`,
  `prep-explainer`, `prep-practice`, `practice`, their `*-results`, `history`, and the
  `*-review` screens (`impromptu-review`, `explain-review`, `storytelling-review`,
  `debate-review`, `prep-review`, `tto-review`) opened from `/history`.

Verbs (`lib/navigation.ts`):
- `enterFlow(href)` — tab → flow. `push` (tabs stays underneath).
- `advanceFlow(href)` — flow step → next step. `replace` (no Back into the finished step). Accepts the `{ pathname, params }` form.
- `restartFlow(href)` — results → start the same flow over. `replace`.
- `exitFlow()` — flow → back to tabs. `canDismiss() ? dismissAll() : replace('/')`.
- `backFlow()` — flow step → the screen that pushed it (single `router.back()` pop). For in-flow Back affordances: the back chevron on `/history` and on the `*-review` screens (a session opened from `/history` pops back to the list, not all the way to the tabs).

Why: a flow calling `router.replace('/')` to "go home" stacks a SECOND tabs
instance instead of returning to the existing one (caused a "home → home"
swipe-back bug). `exitFlow()` is the only correct way back to the tabs.

In-zone moves do NOT use these helpers: switching tabs is the tab bar's job;
paging within one screen (e.g. the explainer's 4 pages) is local state.

Flow screens with in-progress state (`impromptu`, `tto-practice`) disable the
iOS swipe-back gesture in `(app)/_layout.tsx` so users can't bypass the exit
confirmation; `impromptu` re-enables it during its `idle` phase via an inline
`<Stack.Screen options={{ gestureEnabled: phase === 'idle' }} />`.

**Exercise header affordance (2026-07-02):** the four exercise setup screens
(`impromptu`/`debate`/`explain`/`storytelling`) show a **back chevron top-left on
their idle/first screen** (`handleBack → backFlow()`, a plain pop back to the
Practice tab — no confirmation, nothing's started) and swap to the **exit X
top-right + discard confirmation (`handleExit`) once recording begins** (matching
the idle-only swipe-back gating). Idle uses the **`tto-explainer` 3-slot header**:
back chevron (left) · **centered title** (`title` = `flex:1` + `textAlign:'center'`)
· a balancing right `iconSpacer` (so the title truly centers), with the subtitle
below. The title shows on the idle screen ONLY — once recording starts the header is
just `iconSpacer` + the exit X (no title). The shared `ChevronLeftIcon` (path
`m15.75 4.5…`) + `backBtn` (36px, `flex-start`) are copied per-screen like `XIcon`.

## Backend & Database

**Supabase** handles auth (email/password via `supabase.auth`) and the profiles table.

**Profiles table** (`public.profiles`):
```sql
create table public.profiles (
  id uuid primary key references auth.users on delete cascade,
  display_name text,
  current_streak integer not null default 0,  -- daily streak (added 20260609)
  longest_streak integer not null default 0,
  last_active_date date,                       -- user's LOCAL last-practice day
  custom_fillers text[] not null default '{}',  -- per-user custom filler words/phrases (added 20260624)
  pace_target_low integer not null default 130,  -- user's ideal WPM band low (added 20260625)
  pace_target_high integer not null default 160, -- ...band high; CHECK (low < high)
  focus text,                                    -- practice-focus preset key, nullable (added 20260625)
  reminder_enabled boolean not null default false, -- daily practice-reminder on/off (added 20260630)
  reminder_hour integer not null default 19,       -- reminder time, 24h LOCAL (CHECK 0–23)
  reminder_minute integer not null default 0,      -- ...minute (CHECK 0–59); MIRROR of the device-local pref
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

**Row-Level Security (RLS)**: Users can only read/write their own row.

**Auto-create on signup** via trigger `handle_new_user()` — on `auth.users` INSERT, copies `raw_user_meta_data->>'display_name'` into `profiles.display_name`. If the user signs up without a display_name, the field is NULL and the app defaults to `Hi, there`.

**Client-side profile fetching** (`lib/auth.tsx`): `useAuth()` context exposes `{ session, profile, loading, signIn, signUp, signOut, updateDisplayName, updateCustomFillers, updatePassword, deleteAccount }` **plus the email-OTP methods** `{ confirmSignup, resendSignupCode, requestPasswordReset, confirmRecoveryCode, finishRecovery }` and a `recoveryMode` flag. The `Profile` type now carries **`custom_fillers: string[]`** (the `.select()` includes it; defaults `[]`); **`updateCustomFillers(list)`** writes `profiles.custom_fillers` (`.select()`-guarded, RLS-scoped) + patches local state, same pattern as `updateDisplayName` — read at finalize so the user's words merge into filler detection. It ALSO carries **`pace_target_low`/`pace_target_high: number`** (defaults 130/160) with **`updatePaceTarget(low, high)`** (same write pattern) — read at finalize + snapshotted into the session metrics so a custom WPM band drives the pace verdict/colors/score (see `lib/metrics.ts` + `metric-status.ts`) — and **`focus: string | null`** (a preset key from `lib/focus.ts`, null = not set) with **`updateFocus(focus)`** — read at finalize to tune the AI feedback toward the user's goal. ## Streaks (daily streak counter — IN PROGRESS)

**Daily** streak = consecutive **local** days with ≥1 finished session. Strict (miss a local day → resets); no freeze/grace in v1.

**Data model (hybrid — cached counter + recomputable log):**
- `profiles.current_streak`/`longest_streak`/`last_active_date` (cached counter; migration `20260609`).
- `sessions.local_date` (date) — the device's LOCAL calendar day, captured **client-side** at save (only the device knows its tz). The immutable day-bucket + makes the counter recomputable.
- Postgres **AFTER INSERT trigger** `bump_streak_on_session()` (`SECURITY DEFINER`, `for update` lock) maintains the counter from `NEW.local_date` vs stored `last_active_date`: null→1, same-day→no-op, +1 day→increment, **`< last`→ignore** (out-of-order guard), gap≥2→reset 1; then `longest = greatest(...)`.
